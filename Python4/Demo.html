Today we keep three promises

① Every source row is accounted for: in the report, or in a quarantine file with a reason.
② Every failure has a controlled outcome: a row set aside, a run halted, or a model answer marked UNAVAILABLE.
③ A rerun does not repeat business work. A payment, an email or a model call happens once.

Quiz 1 · In check_row, the date is valid. Which blocks run?

D. A missing key is still missing after any wait. A, B and C are temporary problems, so a later try can work.

What we built today

  • Every source row is accepted, or quarantined with a category, a reason and its raw text
  • Four kinds of failure, each with its own outcome, and a halt before any model call when the batch isn’t good enough
  • A stable batch ID, an attempt ID per run, and a rerun that returns the finished result
  • Bounded retries with a cap and jitter, for temporary errors only
  • Four model statuses, checked quotes, a cache of good answers only, and 12 golden cases
  • Eight named checks, and an update the ops lead can act on

A run that finished ≠ a run you can trust.
