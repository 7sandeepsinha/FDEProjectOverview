Four kinds of failure

Each kind of problem gets a name, and the name decides the outcome.

Watch the four words run

Pick a promised date for row C-3003. Green lines run; faded lines are skipped. The terminal shows what Python prints, in order.

def check_row(row):
try:
promised = read_promised(row["promised_date"])
except ValueError:
return "quarantined: promised_date is not a date"
else:
return f"accepted, due {promised.isoformat()}"
finally:
print(f"checked {row['case_id']}")

What Python prints

pick a date

  • Four kinds, four outcomes. A bad row is set aside. A broken rule follows the policy. A missing file stops the run. A failing service is retried, then marked UNAVAILABLE.
  • Our own names. class MalformedRecord(IntakeError) needs no body: the name is the point, and except IntakeError catches the whole family.
  • raise … from error keeps Python’s original error as the “direct cause”, so the traceback reads as one story.
Think of it like thisMaking tea. Try: boil the water. Except: the gas ran out, use the kettle. Else: nothing went wrong, add the leaves. Finally: switch off the stove, every single time.

Read it, or refuse it

A parser accepts a value only when it can read it without guessing. Otherwise it refuses and says why.

The parser bench

Pick a field, then type a value or tap a sample. Every message below is the real one from parsing.py.

Accepted–
Quarantined, with this reason–
  • Shape first, then meaning. 2025-02-30 has the right shape, but February has no 30th, so it is “not a real calendar date”.
  • A guess looks like a fact. 07/03/2025 is 7 March or 3 July. 1.250 is one and a quarter or one thousand two hundred and fifty. Refuse both.
  • Every row leaves through one door. The loader counts a row first, then accepts it or quarantines it with its line number and raw text.
Think of it like thisA barcode will not scan. A good cashier does not type a price that “looks about right”. She sets the item aside, rings up the rest, and calls a supervisor.

  • Cleaning the raw text before saving it. The quarantine keeps the row as it was read.
  • Pasting the loader into python and seeing ...: press Enter once more to finish the loop.

Stop 6 of 9, about 14 minutes

  
Try again, but not forever

  
Retry only what a later try can fix, with a limit and a wait that grows.


  

    
The retry desk

    
Choose what the service does on each attempt. The waits come from random.Random(seed), exactly as in the drill, so seed 4 gives 0.12s and 0.10s.

    

    

      
      3
      
      
    

    

      

        
What the program prints, then the suggestion

        

      

      

    

  


  

    
    
      
  • Retry three things only: a timeout, a 429 and a 5xx server error. A missing key or a bad key never gets better by waiting.
    • 
      
  • The ceiling doubles (0.5, 1, 2, 4, 8 seconds) up to the cap, and the real wait is random below it: full jitter.
    • 
      
  • One retry layer only. The SDK’s own retries are off (max_retries=0), or three attempts inside three attempts makes nine calls.
    • 
    

    
Think of it like thisWhen one bell rings, 800 students reach the gate at once and it jams. If classes leave a minute or two apart, the same students pass easily.

    • 
    
  • Retrying a missing key, which only makes a broken setup slower to report.
    • 
    
  • Known issue in this code: a 529 “overloaded” is not retried. Pick it above and see a single call.

Never invent an answer

  
Every model outcome becomes one status a person can read. The facts from the rules come through whatever the model does.


  

    
The reply judge

    
Pick a note and a reply, or edit the reply yourself. This runs the same checks as interpret_reply.

    

      
      
    

    

    

    
    
    

    
The report line

    

  


  

    
    
      
  • Four statuses: OK, ABSTAINED, INVALID_REPLY and UNAVAILABLE. A failed live call is UNAVAILABLE with a reason, never the recorded answer.
    • 
      
  • The quote must be in the note. If it is not, the answer is kept but flagged, and review is forced on.
    • 
      
  • Only good answers are cached. A cached timeout would be replayed as if it were a fact.
    • 
    

    
Think of it like thisThe weather feed is down. The newsreader says “forecast unavailable this morning”. She does not read yesterday’s forecast, and the headlines still go out on time.

Break it on purpose

    
Each button is a real one-line sabotage of the Final code. The lights show what the full test run reported for it.
