What to remember

  • Underscore, not hyphen: meridian_workbench. Python can’t import a name with a hyphen.
  • __init__.py (two underscores each side) turns the folder into a proper package.
  • The extra src/ layer means a broken install fails on your laptop first, not your colleague’s.
Think of it like thisPans, spices and dirty plates in one kitchen drawer work for one cook. The moment a second person helps, nobody can find anything.
Common slips
  • Creating the project inside another project folder or Git repository. Check the path before you click Open.
  • Typing _init_.py with one underscore. Check the name in the Explorer.
  • Dropping the data files in the root instead of data/.

What does activation actually do?

When you type python, the terminal searches a list of folders called PATH, left to right. The first folder with a Python wins.


    

    

      
    

    
Not active. python means the shared Python every project uses.

  


  
The commands, in order

  
# 1. check you have 3.11 or newer

# 2. create the private environment

# 3. activate it (every new terminal)
source .venv/bin/activate

# 1. check you have 3.11 or newer
py --version
# 2. create the private environment

# 3. activate it (every new terminal)
.venv\Scripts\Activate.ps1
# 4. prove it, don’t assume it

  • Activation adds nothing. It only changes which python answers first.
    • 
      
  • Every new terminal starts fresh, so activate once per terminal. deactivate leaves.
    • 
      
  • Never edit or share .venv. It’s rebuildable, and its paths only exist on your machine.
    • 
    

    
Think of it like thisA shared kitchen cupboard in a flat: two kinds of flour, someone’s old spice spoils your dish. The venv gives each project its own small cupboard.

  

  
Common slips
    
    
  • Windows says “running scripts is disabled”: run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then activate again.
    • 
    
  • Forgetting to activate, so the next install lands in the shared Python.
    • 
    
  • Python 3.9 or 3.10: a tool we need later won’t import. Install 3.11 or newer.
    •

    •

Common slips

    •

    • 
    
  • In PowerShell, $env: stays set until you remove it. A “stuck” date is always this.
    • 
    
  • Adding a secret to .gitignore after it was committed does nothing. It’s already in history. Replace the key.

Proof

  
A test is a small program that checks another program gives the right answer. A check that has never failed hasn’t proved it can.


  

    
Break the rule on purpose

    
In rules.py, CLOSED_STATUSES = {"DELIVERED", "CANCELLED"}. Switch CANCELLED off and watch both programs.

    
    

      
python tests/check_rules.py

      
python -m meridian_workbench

    

    

  


  

    
    
      
  • assert means “this must be true, or stop here and show me the line”.
    • 
      
  • Tests can invent cases your real data may never contain, like a cancelled order.
    • 
      
  • assert belongs in tests. The program itself raises real errors, because Python can be told to skip asserts.
    • 
    

    
Think of it like thisA smoke alarm you’ve never tested. You only trust it after you’ve seen it go off.

  

  
Common slips
    
    
  • Forgetting to put CANCELLED back after the demo.
    • 
    
  • ModuleNotFoundError when running the test: the venv isn’t active.
    • 
    
  • Writing = instead of == inside an assert: SyntaxError.
    •

Common slips
    
    
  • Git asks for a password and rejects yours: GitHub no longer accepts account passwords in the terminal. Use the sign-in method your instructor set up.
    • 
    
  • Creating the GitHub repo with a README, then a “rejected” first push. Create it empty.
    • 
    
  • Forgetting -m and landing in an editor. In vim: Esc, type :q!, Enter.
    • 
    
  • unknown switch 'b': Git is older than 2.28. Run git init, then git branch -M main.
